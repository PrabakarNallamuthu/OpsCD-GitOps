# ADR-001: Backend Language — TypeScript/Node.js 22 LTS + NestJS 10.x

| Field | Value |
|-------|-------|
| **Status** | Accepted |
| **Date** | 2026-08-11 |
| **Category** | Technology |

## Context

The Opsera platform requires 8 backend microservices sharing significant cross-cutting logic (logging, health, validation, Kafka, tracing). A unified language across frontend and backend reduces cognitive load and enables shared type definitions. Node.js 22 LTS provides modern async primitives, V8 engine performance improvements, and is supported until 2027. NestJS 10 provides an enterprise-grade DI framework with module-level isolation, decorator-based routing, and built-in support for Kafka, WebSockets, and health checks.

## Decision

Use **TypeScript 5.x with strict mode** on **Node.js 22 LTS** with **NestJS 10.x** for all 8 backend microservices.

## Alternatives Considered

### Option A: Go (Golang)
**Pros:** Excellent concurrency, low memory footprint, fast startup time.
**Cons:** No shared types with React frontend; smaller team familiarity; no equivalent of NestJS; would require significant framework boilerplate for DI, validation, and OpenAPI generation.

### Option B: Python FastAPI
**Pros:** Excellent for ML/AI workloads; rapid prototyping; strong async support.
**Cons:** No shared types with frontend; Python's GIL limits concurrency; heavier memory footprint than Node.js for I/O-bound services; team expertise is primarily TypeScript.

## Consequences

**Positive:**
- Shared TypeScript types between frontend and backend via `@opsera/*` workspace packages.
- NestJS provides standardized module boundaries aligning with microservice isolation.
- Strong pnpm monorepo tooling for code sharing without duplication.

**Negative:**
- Node.js's single-threaded event loop requires care for CPU-intensive tasks (risk scoring, hash chain verification). Use worker threads where needed.
- NestJS startup time (~800ms) requires startup probe tuning in Kubernetes.

## Compliance Impact

| Framework | Impact |
|-----------|--------|
| SOX       | Consistent logging via shared @opsera/logging package simplifies audit trail. |
| SOC 2     | Strict TypeScript catches type errors that could lead to data exposure bugs. |
| PCI-DSS   | Node.js 22 LTS ensures security patches through 2027. |
| GDPR      | Shared PII masking format applies uniformly across all services. |
| DORA      | Shared test utilities and factories accelerate test coverage. |
