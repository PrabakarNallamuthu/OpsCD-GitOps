# ADR-013: Secret Management — HashiCorp Vault + External Secrets Operator

| Field | Value |
|-------|-------|
| **Status** | Accepted |
| **Date** | 2026-08-11 |
| **Category** | Security |

## Context

8 microservices each require database credentials, Kafka SASL credentials, JWT signing keys, and API keys. Static secrets stored in Kubernetes Secrets are base64-encoded (not encrypted at rest without envelope encryption) and do not rotate automatically. A database credential leak gives permanent access until manually rotated. PCI-DSS DSS Req 8.6.3 mandates credential rotation.

## Decision

Use **HashiCorp Vault** (HA, 3 replicas, Raft storage) for dynamic PostgreSQL credential generation (24h TTL) and static secret storage. Use **External Secrets Operator** to sync secrets from Vault to Kubernetes Secrets with 1-hour refresh. Services read credentials from mounted Kubernetes Secrets; the application layer never contacts Vault directly.

## Alternatives Considered

### Option A: AWS Secrets Manager
**Pros:** Managed service; native Kubernetes integration via ASCP.
**Cons:** Violates cloud-agnostic requirement (ADR-024); vendor lock-in; no transit encryption engine for PII; higher cost at scale.

### Option B: Sealed Secrets (Bitnami)
**Pros:** GitOps-native; simple to operate.
**Cons:** Secrets are static (no rotation); requires re-sealing on key compromise; no dynamic credential generation; no transit engine for PII encryption.

## Consequences

**Positive:**
- Dynamic credentials: each service gets a unique, short-lived database username — a leak expires in 24 hours.
- Vault Transit engine provides AES-256-GCM encryption for PII fields (ADR-022).
- Kubernetes-native: ESO syncs secrets as standard Kubernetes Secrets, requiring no Vault SDK in services.

**Negative:**
- Vault adds operational complexity: HA configuration, auto-unseal, backup procedures.
- ESO sync delay means credential rotation propagates to services within 1 hour, not immediately.

## Compliance Impact

| Framework | Impact |
|-----------|--------|
| SOX       | Audit logging in Vault provides evidence of secret access for SOX CC6.1. |
| SOC 2     | Dynamic credentials satisfy CC6.2 (least privilege) and CC6.3 (key rotation). |
| PCI-DSS   | Req 8.6.3: credential rotation; Req 3.5: encryption key management. |
| GDPR      | Transit engine provides key-deletion-based erasure for Art. 17 compliance. |
| DORA      | Auto-rotation reduces operational risk of manual credential management. |
