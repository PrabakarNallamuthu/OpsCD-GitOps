# ADR-003: Primary Database — PostgreSQL 16

| Field | Value |
|-------|-------|
| **Status** | Accepted |
| **Date** | 2026-08-11 |
| **Category** | Technology |

## Context

The platform stores release metadata, policies, risk assessments, and an immutable audit trail subject to 7-year SOX retention. The database must support:
- ACID transactions for policy evaluations and audit records
- JSONB for flexible metadata (commit details, risk payloads)
- Row-Level Security for audit immutability enforcement
- Monthly range partitioning for the audit trail (billions of rows over 7 years)
- Full-text search is handled by Elasticsearch (ADR-016)

## Decision

Use **PostgreSQL 16** with **per-service schema isolation**, deployed via Bitnami Helm chart with PgBouncer for connection pooling.

## Alternatives Considered

### Option A: CockroachDB
**Pros:** Native multi-region, distributed SQL, automatic sharding.
**Cons:** Does not support all PostgreSQL extensions (pg_partman, pg_stat_statements); higher cost; operational complexity; Prisma support is limited; cloud-agnostic requirement makes the managed service irrelevant.

### Option B: MongoDB
**Pros:** Native JSONB flexibility, easy horizontal scaling.
**Cons:** No ACID multi-document transactions at scale; no native RLS; no partitioning support for the append-only audit pattern; lacks the compliance audit trail guarantees required by SOX.

## Consequences

**Positive:**
- pg_partman provides automated monthly partition creation for audit and analytics tables.
- RLS enforces UPDATE/DELETE restrictions at the database level, not just application level.
- pg_stat_statements provides query-level performance observability for the Grafana dashboard.
- Prisma 5.x has excellent PostgreSQL support including multi-schema and parameterized queries.

**Negative:**
- Single-region deployment creates DR gap (documented in WO-096). Cross-region standby is a future work order.
- Connection pooling via PgBouncer requires careful pool size tuning per service.

## Compliance Impact

| Framework | Impact |
|-----------|--------|
| SOX       | 7-year retention via pg_partman; immutable audit via RLS REVOKE UPDATE/DELETE. |
| SOC 2     | Synchronous commit (synchronous_commit=on) prevents data loss on primary failure. |
| PCI-DSS   | Service-per-schema isolation limits blast radius of credential compromise. |
| GDPR      | Cryptographic erasure for PII fields; per-user data isolation via schema separation. |
| DORA      | pg_stat_statements enables query performance baselining for SLO tracking. |
